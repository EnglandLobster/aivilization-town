# Social Profile Reflection Design

## Purpose

Move social memory consolidation closer to the AIvilization target model where social interaction
does more than update a relationship edge. Repeated lived social experience should also shape the
agent's adaptive profile: habits, values, personality, and social records.

The current backend already records conversations, bidirectional social relation events, STM
records, social long-term records, and social habit insights. This design adds the missing
profile-wide reflection layer without changing world commands or introducing an LLM dependency too
early.

## Current Gap

`AgentStartConversation` and `AgentSocialize` emit `ShortTermMemoryRecorded` entries with
`kind: 'social-interaction'` and a `consolidationHint.kind = 'social'`. Hint-based consolidation
promotes those records into `LongTermMemoryPatch.section = 'socialRecords'`.

`proposeReflectiveInsights` currently filters out all records that already have a
`consolidationHint`. That keeps hint-based patches from duplicating simple reflection, but it also
blocks the strongest social evidence stream from influencing `values` and `personality`. As a
result, repeated conversations can update relation state and social records while leaving the
broader adaptive profile unchanged.

## Design Goals

- Treat social profile adaptation as a memory-domain responsibility, not a worker heuristic.
- Preserve existing social record aggregation and social habit insight behavior.
- Add deterministic, provenance-preserving reflection outputs for `values` and `personality`.
- Consume authoritative social STM records generated by world commands, including records with
  `consolidationHint.kind = 'social'`.
- Keep the output path as `LongTermMemoryPatch` so existing profile repositories remain the durable
  write boundary.
- Leave a clean seam for later LLM-backed reflection without making current tests nondeterministic.

## Non-Goals

- Do not change world command payloads, social relation events, or conversation transcript events.
- Do not add a durable reflection-insight repository in this slice.
- Do not introduce embeddings, vector search, or an LLM profile updater.
- Do not change objective renewal or planner scoring directly.
- Do not infer negative personality or values from failed social interactions yet.

## Proposed Architecture

Keep the existing memory consolidation pipeline:

```text
ShortTermMemoryRecord[]
  -> proposeLongTermMemoryPatches()
  -> proposeReflectiveInsights()
  -> convertReflectiveInsightsToLongTermMemoryPatches()
  -> LongTermProfileRepository.applyPatches()
```

Update reflection internals so record eligibility is decided per insight builder instead of by a
single top-level `consolidationHint === undefined` filter:

- study routine and work caution insights continue to avoid hint-authored pattern records;
- one-target social habit insights keep using successful social context for stable routines;
- new social profile insights explicitly consume successful `social-interaction` records, including
  records with social consolidation hints.

The reflected social profile output should use existing long-term sections:

- `values` for repeated cooperative or community-oriented social behavior;
- `personality` for repeated sociable behavior;
- `habits` for repeated social routine with a specific target, preserving the existing behavior;
- `socialRecords` remains owned by hint-based consolidation, not reflection.

## Reflective Insight Contract

Extend `ReflectiveInsightKind` beyond `habit | caution`:

```ts
type ReflectiveInsightKind = 'habit' | 'caution' | 'value' | 'personality';
```

`convertReflectiveInsightsToLongTermMemoryPatches` maps kinds as follows:

- `habit` -> `section: 'habits'`, `key: topicKey`;
- `caution` -> `section: 'beliefs'`, `key: caution:<topicKey>`;
- `value` -> `section: 'values'`, `key: topicKey`;
- `personality` -> `section: 'personality'`, `key: topicKey`.

Patch ids should stay deterministic and section-aware:

```text
ltm-patch-<agentId>-reflection-<section-name>-<topicKey>-<generatedAt>
```

The old `habit` and `caution` ids remain stable except for internal implementation cleanup.

## Social Profile Insight Rules

The first deterministic rules should be intentionally conservative:

1. Select only records for the requested `agentId`.
2. Select only `status: 'succeeded'` records.
3. Select records with `kind: 'social-interaction'`, or records whose summary/tags contain explicit
   social context such as `social`, `conversation`, `shared`, or `together`.
4. Count a target agent when it appears in `consolidationHint.kind = 'social'.targetAgentId` or in
   the record text/tags as an `agent-*` token.
5. Generate profile-wide `value` and `personality` insights only when there are at least
   `minEvidenceCount` successful social records and at least two distinct target agents.

Initial deterministic insights:

- `kind: 'value'`
- `topicKey: 'community-cooperation'`
- `statement: 'Repeated positive social interactions suggest the agent values cooperative community routines.'`
- `tags: ['social', 'community', 'cooperation', 'value']`

and:

- `kind: 'personality'`
- `topicKey: 'sociable'`
- `statement: 'Repeated positive social interactions with multiple agents suggest a sociable disposition.'`
- `tags: ['social', 'personality', 'sociable']`

Confidence remains the average `importanceScore` of the evidence records. Evidence ids preserve the
same ordering already used by reflection insights.

## Error Handling

- Invalid `minEvidenceCount` and `generatedAt` keep failing fast in the memory domain.
- Missing or malformed target hints do not fail reflection; they simply reduce the distinct target
  count.
- If social records meet evidence count but not distinct-target count, no profile-wide value or
  personality insight is generated.
- Duplicate output keys are resolved by the existing LTM profile upsert behavior, preserving merged
  provenance across patches.

## Testing Strategy

Use TDD at the memory and worker integration boundaries:

- `packages/memory/src/reflection.test.ts`
  - social-interaction records with `consolidationHint.kind = 'social'` generate value and
    personality insights when they span multiple targets;
  - repeated social records for a single target do not create profile-wide value/personality
    insights;
  - study and caution reflection still ignore hinted pattern records.
- `packages/memory/src/reflection.test.ts`
  - converting value/personality insights creates `values` and `personality` LTM patches with stable
    ids, keys, confidence, and provenance.
- `apps/worker/src/memoryConsolidation.test.ts`
  - scheduled or direct consolidation applies social value/personality patches into the long-term
    profile while preserving existing socialRecords patches from social hints.

## Future Extensions

This design leaves room for:

- LLM-backed reflective insight proposers behind the same input/output contract;
- richer personality dimensions once the paper-derived profile schema is expanded;
- negative or cautious social traits after failed or harmful social interactions are represented;
- cross-agent social reflection over shared events and group memberships;
- planner and objective renewal policies that cite value/personality profile evidence directly.
