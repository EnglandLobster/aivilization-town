# Reactive Steering Execution Provenance Design

## Context

The paper's human-in-the-loop steering path requires temporary commands to bypass full
hierarchical BTP, run a localized planner plus simulator/repair, and write the command
plan, execution result, and outcome into short-term memory.

The current local runtime steering world drain already routes `IssueReactiveCommand`
through a localized planner and dispatches accepted command drafts into the world event
stream. However, the reactive steering STM records are persisted before world dispatch.
Their `source.eventIds` therefore remain empty, so the outcome memory cannot be traced
back to the actual world events that executed the temporary command.

## Goal

Make reactive steering outcome memories durable evidence of real execution by linking
them to the world dispatch event IDs generated by `drainLocalRuntimeSteeringCommandsToWorld`.

## Non-goals

- Do not move event-store concepts into `@aivilization/agent-runtime`.
- Do not redesign the append-only short-term memory repository.
- Do not change deterministic localized planner behavior.
- Do not widen this stage to all world-generated action memories.

## Design

- Add a worker-level option to `handleWorkerSteeringCommand` that can defer STM
  persistence while preserving the returned records.
- Keep the existing non-world steering drain behavior unchanged by default.
- In `drainLocalRuntimeSteeringCommandsToWorld`, defer steering STM persistence until
  after command drafts are dispatched.
- When dispatch succeeds, enrich the reactive `:outcome` STM record with the appended
  world event IDs and persist the enriched records once.
- Record steering traces from the same enriched steering result so trace IDs and memory
  record IDs remain consistent with the durable STM repository.

## Verification Plan

- RED: add a local command drain test asserting that the persisted reactive outcome STM
  record contains the real dispatch event IDs.
- GREEN: implement deferred persistence and provenance enrichment at the worker drain
  boundary.
- Regression: run the local command drain test file, the steering test file, then the
  repo quality gates.
