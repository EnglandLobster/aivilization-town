# Agent 驱动社会：边界机制与完整建设 Spec

日期：2026-10-05。状态：建设中，整体未完成。本文是总契约；[能力与实施账本](AGENT_DRIVEN_SOCIETY_CAPABILITY_CONTRACTS.md)是规范性组成部分，必须逐项实现和验收，不能通过改名或移入“以后”来消除未完成项。既有[协作元能力契约](AGENT_DRIVEN_SOCIETY_KERNEL_V1.md)和[验收报告](AGENT_DRIVEN_SOCIETY_V1_VERIFICATION.md)只证明其各自切片。

## 1. 项目到底要造什么

构造一个可信、可行动、可持续运行的世界，让独立 Agent 自己发明社会用途、形成组织、制定制度、执行合作，并修改、退出或放弃它们。我们提供能够长出“社会器官”的原能力，而不是把所有器官的名称、目的和组织形式预写成游戏功能。

完整建设的顺序固定为：界定边界 → 由边界推导所需能力 → 对照源码与运行证据找缺口 → 逐项实现 → 组合验收与自由实验。边界讨论和能力实现是同一目标的前后环节，不能只完成其中之一。

衣食住行、医疗教育、生产交换、家庭社交、组织协作、信息文化、公共治理是检查遗漏的视角，不是要求每种现实机构各写一套状态机。另一方面，账本不能代替真实付款，施工文件不能代替真实建筑。凡是实现这些社会用途必需、且不能由已有原能力组合出的真实效果，都必须补入领域代码。

## 2. 三层职责，以及两个不能混淆的维度

| 层         | 负责的问题                                                         | 不负责的问题                                       |
| ---------- | ------------------------------------------------------------------ | -------------------------------------------------- |
| 规则代码   | 什么操作在当前状态和授权下可以发生；消耗什么；产生哪些可信事实     | 替居民决定值得做什么、谁值得信任、社会应长成什么样 |
| CLI 元能力 | 居民怎样观察、表达、确认、授权、计算、组织资源、采取行动、查询结果 | 因工具名字叫社团/学校/法律就赋予额外权力           |
| AI 与互动  | 目标、意义、解释、伙伴、制度内容、分工、评价、文化、修订和退出     | 靠叙述伪造身份、同意、历史或未发生的资源变化       |

三层不是“代码做硬规则、AI只写文字”。**谁制定规则**与**谁执行规则**必须分别标明。居民可以制定共同支出规则，代码核对其有效授权并执行；开发者不必预设社团用途、会费数值或负责人姓名。

每项规则还要区分以下来源：

| 来源          | 示例                                         | 谁能修改                                                           |
| ------------- | -------------------------------------------- | ------------------------------------------------------------------ |
| 工程可信性    | 身份归属、版本、幂等、事务、历史不可伪造     | 兼容的工程升级；居民不能为一次行为豁免                             |
| 世界模型假设  | 行动需要时间、投入产出、容量、身体效果       | 版本化世界模型升级；居民可以改变状态，不能声明新公式已经生效       |
| 初始制度      | 货币、产权规则、资格门槛、税收、公共授权程序 | 该制度明示的治理程序；暂时没有入口时必须标明固定，不能冒充自然规律 |
| 居民自定制度  | 合作条款、账目规则、支出程序、组织决策方法   | 制度中原先有效的修改程序和受影响资源的有效授权                     |
| 主观解释/习俗 | 名声、感情、正当性、审美、约定俗成           | 各居民形成和改变自己的理解；平台不统一裁判                         |

AMM不等于市场的自然法则；年龄不等于必须退休；文件名“契约”不等于已获得扣款权。社会规则由代码运行，不会改变其来源是居民选择或初始制度这一事实。

## 3. 新需求的边界判定程序

先描述需求造成的效果，再决定是否新增代码。禁止从名词直接推导模块，例如见到“学校”就建立一套强制招生、授课、毕业流程。

1. **拆开三种内容**：居民的意图/说法、可观察的事实、拟改变的权威状态。三者分别保存来源。
2. **仅涉及意义和表达**：使用原文、通信、认知、共享记录；不要加官方分类、评分或成功判定。
3. **涉及已有动作的组织**：使用独立同意、资源权限、有限流程、计划和证据；不要为每种商业模式复制业务引擎。
4. **涉及新的真实效果**：确认现有领域操作无法产生该效果，再补最小但完整的领域原语及其生命周期；给所有合法用途使用，不只给某个预想机构。
5. **涉及约束别人或动用共同资源**：指出授权链、资源范围、有效版本、变更程序、撤回/退出与既有义务；原文声明本身不能制造权限。
6. **涉及主观条件**：决定谁有权作出判断，保存其署名陈述；代码验证“某人作了某声明”，不能假装验证了“质量确实好”。
7. **检查预设偏置**：如果换个组织名字、目标或价值观就必须改核心代码，通常把社会用途写死了。如果写一行文本就能改变物质/资金，通常缺少规则边界。
8. **形成能力契约**：输入、效果、主体、权限、时间、资源、不变量、失败、领域归属、可见性、兼容、验收。没有闭合契约的需求保留为待完成项，不能假成功。

判断结果只有四类：已有原能力组合；缺少通用信息/协调能力；缺少真实世界效果；缺少合法的制度授权/执行路径。不能把后三类全部退回“让AI自己想办法”。

## 4. 事实、陈述、同意、权限与意义

这些记录不能互相替代：

| 记录     | 系统能够保证                                         | 不能据此推断                     |
| -------- | ---------------------------------------------------- | -------------------------------- |
| 世界事实 | 真实执行的转账、库存变化、位置、时间、已建模身体结果 | 合作成功、对方满意、制度正当     |
| 居民陈述 | 谁在何时说了什么、版本和可见范围                     | 陈述为真、说话者拥有其声称的权力 |
| 独立同意 | 谁接受哪个精确版本、回应是否真实                     | 默认无限委托、对后来修订也同意   |
| 操作权限 | 某主体可对特定资源执行何种操作及上限                 | 加入某群就让群主支配财产和身体   |
| 社会解释 | 居民自己的观点、评价和证据引用                       | 全社会统一的信任、爱情或声誉事实 |

同意管的是以谁的身份、对谁控制的资源行使权利，不意味着任何影响他人的行为都需要他人同意。涨价、拒绝合作、竞争、公开批评可以影响别人。税收和正式处置来自明示的公共制度权限。若要支持抢夺、侵害等非自愿物理行为，必须有独立行为和后果模型，不能借“社会真实”开放任意改写他人状态。

四种失败分开：世界不支持/物理不可行；缺权限；承诺未履行；主观不满。前两者可拒绝执行，后两者允许成为社会中的真实结果。不能用“遵守规范”的全局校验提前禁止一切违约、冲突和失败。

## 5. 居民怎样创造可执行制度

制度分成三个对象，它们引用彼此但不自动互相升级权限：

- **原文制度**：目的、条款、例外、解释、争议和成员回应。可完全自由书写。
- **执行定义**：有限、可审查的条件和动作；引用精确版本、资源和可验证依据。
- **授权凭据**：个人授权或有效集体/公共授权；声明谁允许什么、多少、多久、怎样撤回。

工作链：提出原文 → 各人理解/协商 → 发布执行定义 → 受影响主体独立授予精确权限 → 查询/预检 → 执行时复核 → 记录事实与判断来源 → 自主评价和修订。

自然语言不被平台暗中编译成强制效果。Agent可以提出结构化定义，但确认的是可读的确切效果和上限。未被结构化覆盖的条款继续是社会承诺，不因存在一份程序就自动获得强制执行能力。

条件来源必须显式标注：世界事件；当前授权查询；特定人的署名判断；居民自写记录。自写记录可作为本人愿意承担风险的自动化输入，但不升级为世界事实。主观验收可以是买方声明满意，或双方原先授权的仲裁人作出判断；平台只执行已授权的后果。

执行权限按三种来源区分：个人资源授权；共同资源的有效决策凭据；公共制度的辖域授权。不能拿社团多数票扣非成员的钱，不能拿私有程序改税率，不能让普通账本字段代替授权记录。

## 6. 集体治理、公共治理与退出

集体权力要有可追溯的来源，不能只有一个owner管理员：

1. 创建者提出治理章程；其他人独立加入并接受该版本。群成员、共同资源控制人、社会成员身份保持不同事实。
2. 章程定义决策范围、参与者、票数/门槛、期限、执行者、修改和交接程序。系统提供通用程序，不强迫所有组织采用同一种制度。
3. 每次正式决定冻结适用章程和有权参与者；票或签名绑定精确提案。修改内容重新确认；不能降低门槛后追认旧投票。
4. 通过决定产生有限、可消费的执行凭据；真正执行仍检查当前资源、时间和领域条件。投票结果不能造钱、造库存或制造别人同意。
5. 退出停止未来成员权限和新义务；已付费用、已生效订单、债务和托管按原契约处理。不能用退群抹掉事实，也不能用历史同意永远绑住身体行动。
6. 角色交接、成员离线/死亡、组织解散、资源清算必须有确定的状态与授权路径。没有继任授权时停下来，不由平台自动挑选领导者。

公共治理另有辖域和初始权力来源。居民可在既有制度允许范围内提出和修改公共政策；程序验证资格、版本、表态、通过条件、生效时间、公共预算及救济。变更治理程序本身必须按变更前的有效程序处理。系统可信性和物理规则不在普通社会投票的可改范围内。

既有税收、预算、补贴治理只覆盖其实际端口。更一般的集体决策、公共政策入口与执行证据是总能力账本中的建设任务，不能因原来存在请愿命令就标成全部完成。

## 7. 元能力必须形成闭环

| 能力族       | 需要提供什么                                     | 必须保留的自主空间                         |
| ------------ | ------------------------------------------------ | ------------------------------------------ |
| 感知与发现   | 授权观察、按需查询、规则与限制、原文索引         | 居民决定关注什么、怎样解释                 |
| 表达与交流   | 原文、版本、消息、群组、发布、订阅               | 内容、观点、传播意愿与社交关系             |
| 记忆与计算   | 私有认知、可检索经历、共享记录、可追溯的数据处理 | 居民自己的分类、指标与用途；无官方统一评分 |
| 协商与承诺   | 多方版本化提议、逐人确认、履行和争议声明         | 合作条件、信守或违约、是否和解             |
| 权限与代理   | 资源范围、限额、期限、执行者、撤销、交接         | 谁信任谁；什么值得授权                     |
| 资源与行动   | 账户、物品、空间、时间、真实供给与真实后果       | 使用目的、经营组织、价格和分工             |
| 制度与程序   | 可组合的规则定义、集体决定、有界自动执行         | 社团、企业、家庭、治理形式及其制度内容     |
| 连续性与反馈 | 等待、提醒、计划、真实结果、失败恢复、退出       | 是否继续、修订、分裂、放弃或另建           |
| 能力演进     | 发现不支持的效果、提出需求、版本化扩展           | 居民创造新用法，系统不预先穷尽社会形式     |

仅有写文件不够；仅有硬编码行业命令也不够。必须同时有表达层、可组合操作、有效资源授权、真实执行和可感知结果。

## 8. 世界能力怎样支撑社会，而不接管社会

下表是边界验收，不是要预制所有机构：

| 社会用途   | 代码不可缺少的真实效果                              | 元能力如何组织                     | 居民自行决定                      |
| ---------- | --------------------------------------------------- | ---------------------------------- | --------------------------------- |
| 衣食与制作 | 物品、投入、加工时间、使用/食用结果                 | 生产、交换、记录、供给预约         | 菜系、风格、品牌和消费习惯        |
| 居住与建设 | 空间使用权、容量、材料、劳动、建设/维护结果         | 项目、合作、付款、委托、租住       | 开发组织、合住安排、建筑用途      |
| 出行与运输 | 真实路径、时间、载具/装载容量、实际到达             | 报价、同行、货物交付与结算         | 服务模式、目的、线路经营          |
| 医疗与教学 | 已建模身体/学习效果、真实提供者投入、资源和参与时间 | 服务、预约、原文、授权、费用与证据 | 医院/学校组织、教学安排、主观体验 |
| 生产与金融 | 投入产出、所有权、账户、库存、债权和交付            | 雇佣、报价、契约、委托、共同资金   | 商业模式、分工、定价和风险选择    |
| 家庭与照护 | 双方关系确认、真实居住/照护、有限授权               | 通信、共享、约定、参与和退出       | 亲密、家庭习惯、责任的社会意义    |
| 信息与文化 | 作者、版本、可见性、真实传播/阅读                   | 原文、查询、居民自定记录和程序     | 点评平台、报纸、艺术、争论与声誉  |
| 公共事务   | 辖域、有效程序、可执行政策、实际预算和资源          | 提案、表态、决定、执行、争议和变更 | 公共目标、治理形式与价值取舍      |

例如建设：材料与工时是世界约束；谁出资、怎样分工、房屋如何使用可以由居民组织；所有权与开发许可属于明示制度，不能与建筑物是否物理存在混成一条规则。现有“住房容量扩展”不能冒充完整工程过程，这项差距保留在能力账本。

例如学校：到场和授课时间是事实；学习效果是明确的模拟假设；资格认可属于制度；教师评语是署名判断。四者不能用一个“课程完成”字段合并。

## 9. 程序、身体行动与异步协调

居民程序可组合获得授权的操作，但不能绕过领域入口。当前协作v1只有转账、消息、共同记录和定时执行；这一白名单是当前实现边界，不是最终社会能力边界。

需要补齐可追溯的条件、数据查询、居民署名判断和集体执行凭据，使制度能根据事实运行。计算必须有限、输入受权限控制、结果有来源。居民自定排名是某居民/组织的算法输出，不能变成平台默认评分；公共Wiki仍只索引原文。

同步资源操作先预演所有领域决定，再一次提交；长时间行动用明确生命周期，不跨多天持有事务或预先写成功。本人必须亲自开始身体行动；雇主和程序可以发邀请、准备材料、约定报酬，不能替工人到场、替病人接受治疗或替学生学习。

异步协作遵循提出/授权 → 预留 → 本人开始 → 进展/中断 → 完成或失败 → 按实际事实结算。各步骤有幂等ID；取消只释放尚未消耗的资源；已发生劳动不能被回滚抹掉。每个跨领域效果保持原子，整个长期项目不假装是一笔瞬间交易。

## 10. 规则本身的可演进性

每项能力登记：规则来源、状态归属、决策者、执行者、修改权、授权方式、身体参与要求、资源效果、自动化资格、当前可用入口、政策版本和证据级别。

对新需求使用三条通路：

- **社会组合**：已有能力足够，居民直接写原文、建立记录和流程，无需平台新增某种机构。
- **制度修改**：已有执行语义足够，经有效程序修改条款、权限、治理参数；保存提案、签名、旧版本与生效时间。
- **世界扩展**：需要新的真实效果，形成可归属的需求与领域契约，由工程增加能力、事件和验证。不能让居民代码直接改服务器内核，也不能把人工扩展谎称为居民已创造物理规律。

物理接口应允许组合与参数化，避免每出现一种菜系、社团或学校就改世界。仍然不能承诺任意自然语言发明都自动成为可执行物理过程。缺少的真实效果必须被观察到并进入持续开发账本，而非返回伪成功。

## 11. 既有预设的审计与迁移

审计对象包括公式、默认配置、调度、上下文、Agent提示词、初始资产与制度。规则中偷偷代替居民做选择，与提示词强推剧情，都可能破坏自主性。

重点检查：是否用统一幸福值强制迁出；按年龄自动退休；按需求指标自动决定谁建设；用平台声誉决定关系；强制消费和职业选择；全知信息注入；自动替居民判断争议；是否只有开发者预设机构能产生真实服务效果。

迁移不能删除旧事件或静默换公式。保留历史策略，建立显式新社会运行配置，把物理后果、初始制度和居民决策分开。初始需要、资源和公共服务必须标注来源；调度只提供行动机会和结算时间，不替居民选择行动。旧行为只在其旧配置下继续存在，不能混入新模式后称作自然涌现。

## 12. 架构、协调与唯一事实来源

- sim-core：身份引用、命令/事件、模拟时钟、序号和存储原语。
- information：原文、访问权限、通信、共享记录和居民自定数据视图；不拥有经济真相。
- collaboration：协议、独立同意、有限代理、集体决策和执行凭据；不复制账户或世界状态。
- economy/commerce/enterprise/credit：各自的资源数学、交易、企业和信贷不变量；共同资金也必须接入同一会计体系。
- society：身体、生活、学习、居住和现有公共政策规则。复杂新增状态机按真实归属拆分，不继续堆入world。
- services/mobility及必要的新资源领域：真实供给、时间、空间、运输与生命周期，提供最小公开端口。
- world：身份/位置/忙碌校验和跨领域编排，事件原子提交与组合回放。
- agent-runtime/memory：自主目标、解释、计划、记忆；不直接改权威状态。
- apps：CLI/HTTP/模型/观察界面和组装；不复制领域公式，不把模型输出直接当事实。

所有决定为 state + command + versioned policy → events/rejection。reducer只回放已决定事实。执行上下文、规则目录和界面都是读模型，不成为第二套权威。

开放居民运行方式是自主社会的接入入口；当前单写入journal限制必须真实报告。canonical历史行为保持兼容。哪些运行配置和部署路径已接入，每项分别登记，不能把一个实验通过泛化为所有模式已可用。

## 13. 感知、信息边界与持续行动

能力没有被居民发现和使用，就没有完成交付。每项必须包含常态线索、按需CLI、操作回执、经历来源、失败恢复入口，并遵循[上下文交付规范](RESIDENT_CONTEXT_DELIVERY.md)。

默认只给本人状态和有限待处理线索；完整原文、机构规则、账目与计划按需查询。集合分页、大小和排序可验证。当前ACL阻止新的读取；不能假装删除供应商会话中已经见过的内容。收件不代表同意、通知不代表已读、保存记忆不代表每轮召回。

暂停、离线、撤权、拒绝和资源不足都应有可感知的结果。系统不能为了让社会继续运转而自动替居民续约、补钱、选领导或推断满意。操作系统层的模型预算、重试和公平调度应可观测，不暗中被当成居民意愿。

## 14. 验收：证明机制，而不是证明剧情

每项先验收领域与系统边界，再做真实CLI和模型接入。需要覆盖 accepted/rejected/boundary、幂等、版本冲突、撤权、跨领域原子性、资金/物质/时间约束、历史兼容、确定性回放和模拟时间分段等价。

跨用途测试必须证明同一能力可支持不同组织形式，不增加专属机构代码：例如共同记事、居民点评、互助支出、合作生产、教学安排、公共提案。命令序列可以预设用于工程验收，但不能作为自主涌现证据。

真实Agent接入需要独立身份、原始执行记录和权威结果；明确任务提示时，只证明可使用。自由实验不指定组织剧情，不统一目标，不补写失败；允许没有组织形成。追踪自主提出、其他居民独立采用、跨轮维护、修改、交接、退出和失败，分别报告工程可用、被提示采用和自由采用。

不能把“涌现某个成功社会”写成平台必须保证的结果；可以且必须保证创造、执行、观察、修订制度的能力完整可用，并运行不带剧情的实际实验。

## 15. 完整交付的判定与执行纪律

整体完成要求：能力账本所有工程项均完成并有证据；所有用户讨论的领域在三层边界下有真实可用的组合路径；没有用文本替代效果或用代码替代居民意愿；新旧策略兼容；全仓检查通过；真实CLI/Agent和自由运行结果如实报告。

阶段是实施顺序，不是删减目标。新增发现的必要缺口继续登记；不能因难度、耗时或阶段验收通过而宣称整体结束。没有实现的项目保持未完成，不用“规划完成”代替“能力完成”。

工程结果不承诺每种社会形式一定出现，也不穷举现实所有物理细节。这里的完整性是：已讨论社会用途所需的通用动作、世界效果、授权与制度执行、感知和持续演进形成闭环，并有逐项证据。具体实现和未完成工作以规范性能力账本为准。
