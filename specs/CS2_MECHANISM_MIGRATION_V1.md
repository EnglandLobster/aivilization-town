# CS2 客观城市机制迁移 v1

## 目标与边界

参考仓库 `tools/cs2/decomp/Game/Game.Simulation` 的机制关系，以本项目领域事件重写；不复制 CS2 行为决策和游戏数值。身体、资源、时间、容量、空间和明示制度由世界核验；居民自行决定经营、求助、协商、迁居、评价和生活目标。不得用统一幸福值驱动强制消费、退休、迁出或犯罪。

此 Spec 覆盖六个阶段。阶段独立验收，不把已有 CLI 数量当作机制完成。

| 阶段 | 机制与领域归属                                                                         | 交付与验收                                                                                                  |
| ---- | -------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| P1   | 服务供给；services 聚合，world 活动时间端口，enterprise 提供只读雇佣事实               | P1a 实际提供者投入决定同时接待容量；P1b 服务配方/耗材、报酬与企业经营原子结算。预约和接受不保证未来人员到场 |
| P2   | 建筑单元、使用权、设施状态与维护；建立独立 premises 领域，society 继续拥有家庭居住规则 | 房间/商铺容量、明确授权使用、维护材料/劳动、可用状态；产权买卖另定登记与过户制度。原合住租约兼容            |
| P3   | 仓储与货运；独立 logistics 聚合，economy 库存数学                                      | 来源仓库、运输委托、承运人同意、在途托管、到货/退回；货物各阶段不能重复出售，库存守恒                       |
| P4   | 财政投入到公共服务；复用 society publicBudget/serviceQuality 与 world 编排             | 支出购买真实劳动/维护/资源，设施容量影响医疗教育效果；同一笔预算不能同时充当抽象质量加成与实际资源          |
| P5   | 噪声、垃圾、污染；独立 environment 领域                                                | 先按地点/街区累计、传播和清理；确定性采样/回放。客观暴露可影响身体，居民自行解释和采取行动                  |
| P6   | 出行方式与可达性；transport 应用端口与独立运力聚合（必要时）                           | 复用现有道路/拥堵，增加班次、座位、票价与候车；资源预留、取消退款和到达一致，无瞬移                         |

## P1a 本轮实施范围

新增 `resident-services-v3`，新 continuity 实验采用；旧 v1/v2 manifest 和事件语义保留。不迁移旧实验。v3 的 hosted 服务公开 `unitsPerProvider`（默认 1，上限 maxCapacity）作为接待单位约定，仍受服务、时段和真实地点容量限制。该数值是明确的抽象能力假设，不证明专业资格、设备存在、味道或疗效；P1b/P2 再接入具体验证来源。self-service 不获得人工服务效果。

服务可以绑定本人控制的真实活动企业。服务所有者或该企业的实际员工可亲自 `town services start`，在正确位置且空闲时选择提供至哪个模拟时间。招聘名册本身不产生服务，老板不能代替员工开始。该次参与只是服务时间事实，不额外自动发工资；P1b 才统一劳动、工资与投入，现有自愿付款仍可组合。公众可见供给摘要，不泄漏员工余额或私人认知。

每个时段存提供者的实际开始/结束承诺及历史。同一个人不能同时用于多个时段、劳动或旅行。v3 的 `maxProviderShiftsPerSlot` 默认1000，限制单时段历史大小；结束后可自主再次开始。worker 新增对 enterprise 公开 API 的依赖，仅复用 `isEnterpriseOperational` 判定，为 services 注入只读授权端口，不反向依赖 world。接待能力是仍在服务的提供者数量 × unitsPerProvider，并与服务、时段、地点上限取小值。顾客签到必须验证整个所选参与区间的人员覆盖，不能用开始时的容量承诺到员工离开以后。未来预约仍只预留名义席位；不足时拒绝签到并给出稳定原因，顾客可以等待、缩短时间、取消或另选。

`town services stop` 允许提供者亲自提前离场。若剩余投入足以覆盖已有顾客，顾客继续；否则本时段当前参与统一结束并标记 `staffing-interrupted`，释放各自精确活动预留，顾客自行决定后续；不改变任何人的实际位置，也不驱离顾客。不能把中断算成完整履约、不能自动退款或主观裁判。多人释放与服务事件在同一次 journal 提交，任一活动不匹配整体拒绝。

时段的提供者投入和顾客实际参与分别记录。providerOverlapMs 记录至少一名提供者实际覆盖的时间，不把多人重叠重复相加。域内 reducer 只应用最终事实，不根据新规则重算旧事件。

## P1a 上下文、CLI 与 Skill

- 常态：已有 lifeInbox 给本人预约线索，实际开始、离场、中断产生参与者经历；不自动注入全城供给表、人员表或完整合同。
- 按需：`town services read --id …` 返回有界时段及供给（观察时间、容量、当前使用、剩余容量、供给变化时间），完整原服务介绍仍按原文保留。`town bookings read` 获取中断和参与事实。
- 企业成员自主通过服务目录发现关联服务，start 时再次核验当前资格；不存在隐式派工或强制接单。
- CLI 添加 stop，publish 添加可选 enterpriseId/unitsPerProvider；start 兼容旧调用。更新目录与 Skill 版本、manifest provenance。
- 只在开放居民机会循环可见。默认摘要沿用现有 6 条/700 字符等交付预算，查询沿用分页和单次结果上限。canonical planner/分区 authority 暂未接入，不宣称其支持。

## 后续阶段的感知与自主行动约束

| 阶段 | 默认感知                            | 主动 CLI（未来接口方向，尚未实现） |
| ---- | ----------------------------------- | ---------------------------------- |
| P1b  | 本人服务缺料/履约结果的经历线索     | 配方、耗材、成本、报酬明细         |
| P2   | 本人住所/场所故障或使用权变动线索   | 房源、空间合同、维修委托、产权记录 |
| P3   | 本人发货/到货/延误通知元数据        | 物流报价、运输状态、仓储库存       |
| P4   | 本人实际等待/服务结果；公开预算入口 | 公共预算、容量、覆盖与账目         |
| P5   | 所在地点可感知暴露和本人身体结果    | 区域环境、治理方案、来源证据       |
| P6   | 本人旅程/班次变化                   | 路线、票价、时刻、余位             |

各阶段实施前必须补齐数值 policy、聚合及命令/事件 schema、通知上限与排序，不能凭该方向表宣称已有能力。全城信息均按需授权查询，不默认广播。

## 验收

P1a 覆盖：合法/非法发布、企业授权、员工独立开始、地点/忙碌拒绝、缺员及跨结束边界容量、短参与、多人供给、提前离场与中断、多聚合原子拒绝、资金库存未变化、旧策略兼容、事件回放、一次/分段时间推进等价。再运行真实 CLI 子进程、Skill 验证、lint、全仓 typecheck/tests 与相关 build。

后续资金或物流阶段必须新增复式会计/库存守恒测试；建筑阶段需覆盖使用权互斥与租约迁移；环境阶段需覆盖种子确定性。实验自由运行另行记录，不指定剧情，不把模型叙述当世界事实。

## 当前状态

P1a 已实现并通过工程与真实 CLI 验收，见 [验证记录](CS2_SERVICE_SUPPLY_P1A_VERIFICATION.md)；P1b 与 P2–P6 已规划、未实现。本轮不承诺完整医院、学校、房地产或物流市场已经建成。
