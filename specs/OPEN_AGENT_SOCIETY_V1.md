# Open Agent Society v1 Spec

状态：v1 已实现，真实驱动与回归验收见配套实施报告。日期：2026-09-25。来源：[讨论纪要与架构方案](https://my.feishu.cn/docx/GSkYdrg8HouFdcxeStscsNv9nRe)，revision 4。

## 1. 目标与范围

实现可运行的开放居民模式：市民具有持续身份、个人认知、真实经历、有限观察与通用信息空间，能自主发现工具、获取信息、改变打算和调用正式世界能力。工具执行结果可靠持久化，可恢复、审计和回放。使用 OpenCode 作为真实模型居民驱动器，验证多人、多次唤醒的完整链路。

实现单位是可组合机制。点评网站、社团、耳濡目染、旅游均是观察题，不成为必然发生的剧情、提示词候选或专用业务开关。

v1 是独立可运行、单权威进程的实验部署，复用现有 `world` 领域与事件语义，不与旧 daemon 同时写同一实验目录。支持多居民独立身份和持续活动；不声称已经证明几万人模型吞吐或人类心理真实性。旧 canonical 模式及历史数据保持兼容。跨进程/多分区部署沿用后续扩展端口，不在 v1 中制造第二套经济规则。

## 2. 领域与依赖

| 所属                   | 权威状态/职责                                                  | 不变量                                                                       |
| ---------------------- | -------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `information` 新领域包 | 共享空间、文件、作者、消息、权限与修订事件                     | 路径规范化、作者绑定、版本冲突、私密性、不可覆盖他人文档、已删除版本保留     |
| `memory`               | 私人认知条目、目标/认识/笔记、个人经历                         | 事实/个人认识分离、证据引用归属、版本检查、旧记录兼容                        |
| `agent-runtime`        | 能力描述、调用与循环端口、上下文预算、唤醒/会话策略            | 能力集合不依赖 deterministic proposer，允许结束/等待，预算明确               |
| `world` 与现有领域     | 身体、空间、会计、生产、企业与活动                             | 继续由 `dispatchWorldCommand` 和 `applyWorldEvent` 决定与回放                |
| `worker`               | 开放社会应用编排、持久化 journal、观察 adapter、执行与唤醒队列 | 单写入者、请求去重、原子提交世界/认知/信息事件、重放相同状态                 |
| `apps/residents`       | HTTP、CLI、OpenCode 驱动、运行报告与观察入口                   | 认证绑定居民；模型仅能执行受限 town 命令，没有任意宿主终端或其他居民身份权限 |

`information` 当前无运行时依赖；允许内向依赖 `sim-core`；`memory` 保持现有内向依赖；`agent-runtime` 通过端口访问外部能力；`worker` 依赖公开领域 export；`residents` 仅作为外层 adapter。新增依赖用于真正的权限/修订聚合边界，不设通用业务大杂烩。

## 3. 运行模式与持续状态

一次唤醒形成 turn：`ready -> running -> waiting | completed | budget-exhausted | provider-error`。

1. runtime 按模拟时间选择 due 居民，以最近获机会顺序公平轮转。
2. 绑定本轮居民身份，提供必要初始上下文和能力入口。
3. 驱动器由模型自主选择查询、认知更新、文件/消息、世界命令；工具执行可以多轮交错。
4. `schedule.wait` 记录下次时间/事件等待与交接摘要。模型纯文本结束不自动制造世界行动。
5. 消息、提醒、活动完成或下一次自由活动机会使居民再次 ready；等待不冻结世界。
6. 运行器在轮次边界通过现有时间推进命令推进模拟。自由运行每机会消耗 opportunityCadenceMs（默认 1,000ms；旧 v1 manifest 缺失该可选字段时取同值），避免消息互发让时钟停住。链路验收每完成一轮居民机会，还显式推进到最近活动到期以检查到达；该时间推进属于测试编排。居民无权直接改世界时钟。

不要求必须有长期经济目标、必须选出一个动作或必须接受推荐。提供预算和公平的自由活动机会；不把缺钱/饥饿直接翻译为强制行动。模型故障留真实失败记录，绝不冒充成功或暗中用脚本代办。

## 4. 初始上下文与预算

初始包包括：身份/初始化背景、模拟时刻与世界 revision、唤醒原因、自身身体/资源/地点/当前活动、近期未读通知、有界认知摘要、相关经历引用、工具分类与展开入口。

v1 初始策略为 `open-agent-context-v1`：认知最多 8 条、近期经历最多 6 条、未读消息最多 6 条、可见人物摘要最多 12 条；每次查询默认 10 条、最大 30 条；单条文本最多 8,000 字符。超限返回总数/游标或明确的截断提示，可再检索和展开。每次工具返回还受结果体量上限约束。

这些是版本化工程预算，不是人的记忆容量或自然规律。紧急身体状态、到期事项和执行反馈优先，其他内容确定性排序。完整数据库不得默认注入所有规划阶段。

市民查询：自身精确信息；当前地点可见人物的公开身份；本人收发消息；本人经历与认知；公开或获授权文件；当前可交易市场价格和公开设施信息。别人的余额、私人认知、全量关系和未公开计划不可读取。目标 ID 不等于获得访问权限。

查询信息区分 `world-fact`、`firsthand`、`message/claim`、`self-belief`、`initial-background`。外部文本始终是数据，不能成为权限或系统指令。

## 5. 能力接口

模型不接收由规则筛选的 action menu。`capabilities.search/list/describe` 发现正式能力；初始不展示某工具不等于禁止使用。

居民通过 `town` CLI 操作，使用 `town wiki` 按索引读取 Skill、通过分类和命令 `--help` 按需发现参数。所有现有能力均映射为具名命令；HTTP 注册表仍是服务端应用端口，不向居民暴露业务 MCP。详见 `RESIDENT_CLI_SKILL_V1.md`。

| 类别       | 正式能力                                                                                                                                  |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 世界读取   | `world.observe`（self/location/locations/market/rules/action/enterprises），只读权威投影                                                  |
| 记忆       | `memory.search`、`memory.read`，全历史可检索、原始来源可展开                                                                              |
| 认知       | `cognition.list`、`cognition.update`，belief/goal/note/self 类型，expectedRevision                                                        |
| 空间与文件 | `spaces.create/list`、`files.create/read/list/search/update/delete/history`                                                               |
| 消息       | `messages.send/list/read`，作者由认证绑定，接收者独立选择如何回应                                                                         |
| 时间       | `schedule.wait`、`schedule.remind/list/cancel`                                                                                            |
| 行动       | 正式 world 命令的具名能力（如 `world.move`、trade、eat、sleep、study、work、production、enterprise、credit 等），通过公共 dispatcher 处理 |

所有 schema 区分 Agent 可选参数与系统权威参数。actor、command ID、模拟时间、教育效率、结算价格、关系增量等权威值由 runtime/领域提供，不能接受模型伪造。社会交流通过真实单方消息及回应，不允许一个居民代写对方同意或任意修改客观关系。

## 6. 信息聚合

空间：id、owner、title、visibility（public/private）、投稿权限（owner/members/everyone）、members、revision。文档：spaceId、规范化相对路径、authorId、正文、revision、createdAt、updatedAt、deleted（tombstone）与 updatedAt。消息：id、sender、recipient、正文、时间与阅读状态。

写入决策：`state + actor + command + policy -> events | rejection`。空间控制访问和创建权限；文档作者控制更新，空间所有者具有明确的管理删除权限。内容不能修改 ACL。公开投稿允许创建本人独立文档，不允许覆盖其他作者。路径拒绝 `..`、绝对宿主路径、空段及保留地址歧义。

更新和删除要求 expectedRevision。删除保留 tombstone 与历史事件。查询、历史和搜索都进行权限过滤；缺失与无权资源对未授权者返回不泄露私密存在性的错误。单条、空间数和正文大小均有 policy 上限。

普通文件不产生转账、产权和债务；若正文写着“已支付”，系统仅记录该说法。点评可有真实就餐事件引用，也可无凭据发表主观说法，不能自动伪造验证标记。

## 7. 认知与经历

认知记录：owner、key、kind、statement、confidence、evidenceIds、revision、updatedAt、active。更新限定本人，以版本检查维护一致性。引用事件/记忆须本人可见。想法没有外部证据时可以留空，但不得称为已发生事实。自我描述变化不意味着世界客观状态变化。

经历自动来自真实执行结果、消息收发与可见活动事件，含 source ID、模拟时刻、来源种类和状态。拒绝同样可成为经历。读取与普通检索不无限生成重复记忆。写入请求与经历在同一 journal commit 中落盘；重放不二次产生经历。按人物/文本/时间检索，支持稳定分页；v1 不要求 embedding 依赖，但检索端口可替换。

旧 memory profile 和 intention 概念继续兼容；开放模式中的自主认知使用明确版本的记录，不静默改写旧 profile 和事件语义。客观关系继续读取 society/world 权威；主观印象保存在本人 cognition。

## 8. 原子性、恢复与安全边界

一条持久 commit 包含 schemaVersion、通过 manifest 绑定的 policy versions、sequence、模拟时间、actor、requestId、requestFingerprint、各领域事件、工具结果和必要 trace。先验证全部事件可应用，再追加并 fsync，成功后发布新内存状态。一次操作的全部效果在同一记录中；损坏/截断 journal fail closed，不静默吞掉。

相同 actor/requestId 和相同参数返回原结果；相同 ID 不同参数拒绝。所有写入在单权威进程串行化；独占锁阻止第二 writer。磁盘文件使用受限权限，应用通过逻辑 ID 访问。崩溃重启重放提交，不能重跑模型或重复执行世界动作。快照/manifest 包含 initial state、世界 policy 与新策略版本。

world 写入只经 dispatcher。系统时间用于进程超时和锁，不决定领域结果。服务器只监听 loopback 作为本地实验入口；每名居民独立 token，管理端独立 token。居民 CLI 不提供其他身份或管理员端点。

## 9. OpenCode 接入与真实实验

本机已检测到 OpenCode 1.18.32 和可用认证；不读取或输出密钥内容。驱动器启动隔离的居民工作目录，绑定该居民 CLI 凭证，禁用任意宿主 shell、文件编辑、任意网页和子代理，只开放经过预检的受限命令执行器运行 town CLI。模型可通过我们的通用文件接口改变模拟信息空间。

每名居民独立会话。驱动器记录 provider/model、OpenCode 版本、会话 ID、实际输入输出与使用量（若返回）、工具调用、世界事件和运行耗时。不记录凭证。模型返回正文不当作已完成的行为。

实验分两类：

1. **链路验收**：明确标记为测试指令，要求真实模型验证能力发现、检索、认知更新、公共文件、跨居民消息、世界移动/执行反馈以及等待后再唤醒。结果只证明接入与执行链路，不作为自然涌现证据。
2. **自由运行**：不注入这些验收任务；提供背景和自由活动机会，记录实际发生或未发生的行为。不得为了指标强制重复抽样直到产生预定剧情。

首轮至少两名真实 AI 居民、多轮次运行；保存可复核报告与原始工具/事件引用。模型不可用需报告真实错误，但继续完成可独立的实现和自动化测试。

## 10. 观察与使用入口

提供独立居民实验 CLI（初始化/服务/工具调用/时间推进/运行/报告）以及只读观察页面/API，展示居民状态、公开信息空间、工具轨迹、记忆来源和世界事件。观察入口明确管理员全局视角与居民有限视角。旧镇前端不读取伪造“内心独白”。

## 11. 验收矩阵

- Information：接受/拒绝、边界、路径、ACL、作者绑定、版本冲突、历史/删除、事件重放。
- Memory：本人读写、证据隔离、事实与信念分离、版本冲突、检索分页、归档检索、重放。
- Runtime：能力不依赖 proposer；预算限制；身份隔离；不同 payload 相同 requestId；重试去重；持久恢复；消息唤醒与等待；模拟时间；跨领域原子性。
- World：真实移动/到达与忙碌拒绝，经济指令复用领域校验，非法参数拒绝，资金/库存不变量，回放等价。
- Transport：全部 CLI 能力路由、类型参数、错误/断连/幂等重试、受限执行器拒绝宿主命令；HTTP 限制与认证；原文与回放；OpenCode 配置不泄露认证。
- Experimental：真实模型调用证据、两名居民隔离、跨轮次持续状态；区分链路测试与自主现象。
- Repository：format、lint、全仓 typecheck、全仓 tests、相关公开包 build；现有前端更改不回退。

## 12. 兼容、推广和停止

本轮新增实验入口，不更改旧运行默认值。新 policy/schema 单独版本化并写进 manifest；既有事件保留原义。异常时停止接收新写命令并保留 journal。切换回旧模式不会撤销已经发生的事实；恢复用独立实验目录重放，不覆写旧 daemon 数据。

发布前必须将本 Spec 的接口、实际命令、测试结果与真实限制同步到实施报告。后续跨分区、多进程、向量记忆与 Agent 可执行应用，依据实际瓶颈继续扩展；不以它们尚未实现否定本轮完整单权威链路，也不宣称已具备这些能力。
