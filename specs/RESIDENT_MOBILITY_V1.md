# 居民网约车 v1

## 目标与边界

让居民自行决定是否开车、发布出行需求、报价、选择司机和评价经历。平台不制造需求、不自动派单、不规定职业、不生成评价排名。居民入口仅为 town CLI，按需索引 Skill。

`@aivilization/mobility` 拥有车辆及驾驶授权、司机登记/在线状态、报价和行程聚合，纯决策和最终事实事件。车辆 ID 唯一、一次只能承担一个行程；司机/乘客不能同时接受多个行程。World 拥有地点、道路、真实旅行、账户以及跨聚合原子编排；commerce 提供既有复式托管。Worker 只做身份适配、查询、调度与 journal 提交。

## 初始化与兼容

版本 resident-mobility-v1。新 continuity 开放实验且启用生活模块时显式播种一辆双座车，归第一位居民所有，初始位置与车主相同。该有限资产作为 manifest 的初始条件与 provenance 保存，不是赚取或购买的历史，也不自动注册司机。允许显式关闭 mobility。旧 manifest/快照没有 mobility 字段则保持关闭，不补造车辆。专用押金前缀保护仅在启用出行的世界生效，旧实验既有同名普通押金仍按原契约处理。领域初始化支持显式多辆种子车；本版无车辆生产、买卖或付费租赁，车主可授予/撤销免费驾驶授权。

## CLI 与流程

- vehicles list/read：查询自有/获授权车辆、真实停车地点和占用状态。
- vehicles authorize/revoke：车主授权/撤销另一居民，带 expectedRevision；有活动订单/移动时不得变更授权。
- drivers register：本人选择已获授权、空闲车辆；注册默认离线。drivers online/offline：自主开关接单；下线不取消已承诺行程。drivers list：本人登记及公开在线司机。
- rides request：本人在实际出发地点发布需求，指定 destinationId、expiresAt。单乘客，不生成虚拟随行人员。一次只能有一个未结束需求。
- rides list：mine（本人历史）或 open（公开未成交需求），分页。rides read：需求阶段公开路线/期限；成交详情仅双方可见。rides quotes：乘客查询本单报价，司机只能查询自己的报价。
- rides quote：在线司机选择需求，给出固定 fare 和 expiresAt；报价不可暗改，撤销后可另报。过期/撤销报价不能选。
- rides withdraw：司机撤销本人尚未成交报价。
- rides book：乘客选择未过期报价，携带订单 expectedRevision。原子检查双方/车辆无其他活动行程并托管全部车费。报价是司机对该路线、固定价格及乘客到场上车后发车的事先同意。
- rides pickup：司机亲自到所选车辆位置，空闲后驾驶车辆前往接客点。车辆与司机共同移动；就在接客点则进入 ready。
- rides board：仅乘客本人，在司机和车辆均实际抵达、双方空闲时上车。为双方生成完全相同的路线、出发和抵达时间。车辆、司机、乘客共同占用该行程。
- rides cancel：任一成交方可在载客出发前取消；乘客可取消未成交需求。全额退款，无暗扣取消费。司机已在接客途中时，取消不会瞬移停车；该车辆直到真实抵达才可再次使用。
- 模拟时间到达真实目的地后，自动完成并将已托管车费转给司机；多次推进或重放不能重复收费。未上车的需求到期自动取消退款。

时间单位为 simulation milliseconds；报价到期不能晚于需求期限。首次使用可 `town help rides`、`town rides request --help` 查看实际格式。价格由司机提出，乘客自主同意，不由模型直接改余额。免费帮助可通过已有协作能力，v1 车费为正数、有上限。

## 事实、不变量与结算

- 路线由已有空间图计算；v1 沿用现有旅行时间与拥堵规则，没有宣称汽车比步行快。每个座位仍占用目的地容量，联合发车前一次检查两人容量。
- 车的位置只随有驾驶者的已记录行程变化，司机自行步行不能带走车辆。车辆在途中不能重复登记、授权或接单。
- 用 `ride-deposit-<orderId>` 托管，公共 deposits 命令不能提前释放或结算该命名空间。只允许 world 出行应用端口在已接受的领域决定后协调付款。托管计入既有 resident-commerce 流通账户，moneySupply 不变。
- 财务、车辆、订单及双方旅行事件一次提交；任何授权/余额/容量失败都没有部分效果。
- 保存最终状态和版本，不在 reducer 重算价格、路线或到期规则。scheduler 枚举到期和到达边界；大步推进与逐边界推进的出行结果一致。
- 上车后不可用取消命令瞬间下车；v1 不支持中途停靠/改目的地。自由文本投诉、评价使用已有原文信息空间/消息，平台不判定满意度、不生成信用分、不自动退款；争议赔付可由双方主动转账。此限制在 Skill 明示。

## 上下文交付

常态仅将本人未结束行程/乘客收到有效报价/司机已成交订单的 id、状态、期限和 readWith 放入现有 lifeInbox 共享最多 6 条预算；沿用 decisions/appointments/messages 轮询、期限优先、稳定 ID 排序及 total/shown，不新增整段全城信息。

车辆、在线司机、公开需求、报价与历史均主动 CLI 查询，最多 30 条/页。详情保护双方隐私；原文评价不常态注入。行动回执是本次状态与事件，相关双方在订单状态改变时各获可检索的事实经历；经历存储不意味着自动全量召回。沿用有界记忆与 provider 会话历史语义，不声称删除先前上下文。Skill 根索引 → life/mobility → 命令组页，按需展开。只对开放居民 context 生效，不扩展 canonical planner stages。

## 验收

领域：接受/拒绝、身份、版本、金额/时间边界、过期、车辆/人员排他、取消与到达、事件回放。
World/runtime：双人共同行程、接客与车辆位置、目的地容量、资金守恒、余额不足无部分效果、托管旁路拒绝、取消途中保持实际位置、到期退款、重复请求幂等、时间跨界等价、旧 manifest 关闭与 journal 重启回放。
真实 CLI：两居民注册上线、需求、报价、托管、接客、上车、到达结算；另验证取消退款。全仓 lint/typecheck/tests 和相关 build。

## 明确未包含

自动派单、多人拼车、计价器、车辆生产/买卖/付费租赁、燃油维修、驾驶资质模拟、道路车流单位重建、公交地铁与财政建设；canonical daemon/分区 authority 接入。实验成功不能视作这些能力已经完成。

本版闭环已实现；[验收记录](RESIDENT_MOBILITY_V1_VERIFICATION.md)包含实际 CLI 证据及明确范围限制。
