# 原子资源交换与明确代理：W05 / M04 / M07

状态：个人六类资源的有偿原子交割工程验收通过（2558通过/1跳过）；集体、service、车辆、企业、长期义务及全模式继续。它们属于同一完整目标，不能因首批原语可用而关闭本文件。

## 1. 为什么继续扩展组合能力

一次有偿交割包含双方同意、资源控制变化和资金变化。居民可以把它用于转让店铺、共同仓库、信息空间或其他已经存在的资源。用途、价格、交易组织和称谓由居民定义。代码需要保证精确授权、真实交割和原子性，不能按“开发商”“企业社团”等预设剧情决定谁应该拥有资源。

当前 programs 已有逐人授权、版本、次数、到期、撤回、条件与整体成功/失败，但可执行动作只有付款、消息和记录写入。资源控制的各领域已经有独立 offer/accept。直接增加“出售房屋”之外，还必须补齐这些原语之间的组合边界，否则每换一个社会用途都会继续堆专门路径。

有偿定期许可仍由 premises 计量、commerce 结算：它涉及长时间内持续供给，不能用一次原子交割冒充全部履约。原子控制交换和有偿定期许可是不同事实类型。

## 2. 封闭动作与居民定义的组合

新版本程序只允许登记过的无外部副作用领域动作。每项动作必须声明：所属聚合、读取的精确版本、实际授权主体、可否委托、产生的事件族、重放验证、是否改变资金或控制，以及对应可读入口。

第一组交割动作覆盖现有资源的控制 offer / accept / cancel 和资金转移，按所属领域建立 adapter：premises 建筑、materials 库存、information 空间/共享登记/视图/通信组、services 已支持的管理资源。车辆、企业等缺少相应控制原语的资源在所属领域补齐，再接入同一清单；不能用通用 ownerId 覆盖其规则。完整矩阵必须逐项保留，不能把暂未接入改称范围外。

居民自行编排“卖方给出这一版本的移交、买方接受、买方付款”等步骤。全部当事方必须为这一份程序及版本独立授权；只有两边都同意才可能运行。不需要平台预造商业名称、企业组织或价格策略。

同一原子执行内生成的控制报价只能被该执行的后续明确步骤使用；没有中途可见的免费可领取报价。若引用执行前已存在的普通报价，必须把它是独立无条件移交、还是受已接受交易约束说清楚，不能擅自给旧报价追加收费限制。新程序不能把撤回后的授权、已耗尽次数或旧控制版本重新激活。

## 3. 代理执行不能伪装本人行动

每次执行必须区分：资源主体 principal、实际运行者 executor、原始授权人、授权版本、授权次数、程序版本、当前步骤与精确动作。命令中的主体字段只是请求，必须与独立授权记录吻合。

当前 personal controller 校验只允许本人，collective 使用精确决定；不能通过把 runner 改名为 principal 就悄悄放开全部能力。新程序代理必须有显式版本和封闭动作清单，持久事件/回执保留 executedBy 与 programRun/mandate 引用；读取时不能把代理结果描述为本人现场签字。旧无代理元数据的事件保留原解释。

身体行动、到场、治疗同意、实际工作、入学学习、投票及个人观点署名不能借资源代理启动。集体使用共同账户或共有资源时，还须有当前章程下的有效决定；个人程序授权不替代集体同意。集体决定批准精确程序/动作，消耗决定凭据与实际效果必须同一提交。

## 4. 原子提交与回放

执行先读取真实状态、检查所有授权及条件，在临时状态上按明确顺序调用所属领域决策。一个步骤失败，丢弃全部领域效果；保留失败原因和尝试记录，不扣款、不交割、不消耗成功次数。任何网络调用、模型输出或外部发送不能放入这种可回滚的临时执行；居民世界内消息仍是信息事件。

现有 OpenSocietyEffects 以事件族合并，单族内保序，但不能直接据此保证任意跨族交错。新组合必须使用版本化、有界的有序步骤提交结构；回放沿原步骤验证并应用，不能将运行时依赖 A→B→A 重排为 A→A→B。结构中每步只容纳已登记效果，禁止任意嵌套程序、任意命令代理或执行代码。

完整提交需要验证：原程序及版本、逐人授权、当前可执行次数、各步骤真实领域结果、跨账户平衡及最终资源版本。不能删掉付款步骤而仍成功消费整个授权，也不能只保留交割事件。不使用事后补偿来假装原子性。

旧 journal 的 v1 扁平效果及旧程序事件继续原义；新结构必须有独立 schema/policy 和显式启用。恢复过程不能自动重试已成功提交的对外动作。未来 canonical/partition 接入沿用同一领域和原子承诺，不能另造不同含义的路径。

## 5. 权利与责任的连续性

交割改变实际管理控制，保留原作者、历史记录、资源所在位置、现有存货、第三人许可、租约、保管、未结束服务及债务。原创建者不会因为作者字段未变继续拥有管理权。买受人也不能因接手就读取第三人的私人记录或撤销其已经生效的许可。

公众土地配置权与私人建筑控制权分开；不能转让平台没有授予的土地所有权。库存控制交接不自动搬运库存，信息资源控制交接不自动改变原文作者，通信组管理员交接不等于成员同意更换所有群规。

价款和移交必须按精确授权解释。交割事实不等于满意、合法争议已消失或购买目的已经实现。后续争议、收益/责任转让、撤销与救济须使用已有原文和明确授权；不能把钱退了就抹掉曾发生的控制变化。

## 7. 已接通的基础范围与提交格式

`resident-program-actions-v2` 是显式版本化的封闭语法。新定义必须包含 actionPolicyVersion，新增 `resource.control` 的参数为资源种类、ID、精确修订与原始 ControlCommand。当前登记 premises/stock/space/register/view/group，主体是个人；它们仍经过各自领域校验。service、车辆、企业与集体组合保留在完整清单，不能伪装成某种已支持的资源。

新 manifest 只有显式 `programActions: true` 才启用；旧实验由运行者执行 `enable-program-actions --root DIR` 写入一次 `ProgramActionsEnabled` 事件。缺少策略的旧 manifest、旧无 actionPolicyVersion 的程序和旧 journal 保持原义。启用状态及版本由 `town rules read --id resident-program-actions` 与规则政策查询展示，不把启用操作交给居民。

ProgramStepAuthority 来自当前独立授权，记录 programId/revision、runId、stepIndex、principalId、executedBy、mandateId/revision、模拟时间。解析不消费授权。`ProgramRun.execution` 记录每步 authority 及原始领域事件的 SHA256 摘要指纹；不复制私人原文到新账本。`town programs runs` 仅向参与者分页提供回执。

`ordered-society-effects-v1` 只增加 family/index 引用序列；原始事件仍各存一份。每个实际领域事件出现且只出现一次，同领域索引递增，跨领域顺序严格保留。程序后续步骤、定时推进、反应排队和反应结果追加都重定位引用，而不按领域重排。未标记的历史事件保留原固定族顺序。

应用 admission 在临时状态按原步骤调用所属领域，资源代理实际 executor 通过回执与经历明确归因。最后付款不足时，临时 offer/accept 丢弃，真实资源、余额、成功次数均不改变。成功时所有领域效果与精确授权次数变化同一提交。失败可以留尝试记录，不记录成功步骤。

回放先检查每个 run 的独立授权、完整步骤数量、精确执行者及版本，再核对连续事件的摘要引用和原动作与实际领域结果的机械对应。付款必须是原主体、原收款方、原金额的平衡交易；消息保留原文和代理标记；记录保留实际编辑者和授权主体；资源只可改变该次控制版本。改变金额后重算摘要也无法绕过原始授权。最后核对所属 coordination 的完整次数/计划回执。资源和账户仍由各自 reducer 应用，不调用 CLI、网络、模型或实时决策 adapter。

控制交割保留原作者、原内容、库存、地点和其他聚合的权利。登记簿清除旧 successor 提名，群组控制交接按其原领域规则使旧待接受邀请失效，已加入成员不被改写。原控制人不因 ownerId 作为历史字段仍然存在而继续取得管理权。

工程验收脚本：`apps/residents/scripts/verify-atomic-exchange.mjs`。真实编译 CLI/HTTP 已跑 76 次调用，其中 20 次预期拒绝，实际建设、六类交割、独立授权、末步失败、幂等、私密读取、旧控制人失权及整本 journal 重启一致已验证；记录见 `evidence/SOCIETY_ATOMIC_EXCHANGE_2026-10-05.json`。没有调用模型，不能解释为自主涌现。
