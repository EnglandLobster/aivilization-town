# 共同资源与账户：M06/M09 实施契约

状态：账户切片完成工程验收（[证据](SOCIETY_COMMON_ACCOUNTS_VERIFICATION.md)）；其他共同资源与跨资产清算仍待接入。此文是完整社会能力账本的子契约。共同账户完成后仍须把空间、设施、经营和长期义务接入同一控制原则；不得把余额账户等同于全部共同资源。

## 归属和事实

`economy` 拥有 CommonAccount 的现金状态、版本、状态机、预算与平衡交易。它不依赖 collaboration，不知道社团用途。`collaboration` 拥有控制这个账户的集体及精确决定凭据；world 应用端口原子编排账户与居民/企业/国库余额，开放居民应用将 world 事件与决定消费同次提交。普通共享表中的余额永远不是这个账户。

引入明确的 `collective` 流通会计部门，账户 ID 为 `collective:<accountId>`。不是 public-service，也不是企业或某位负责人的个人余额。所有国内转入/转出均是 transfer，不改变 moneySupply。经济构成、对账与观察器必须计入共同账户；旧事件和旧快照缺少该字段时按无此功能处理。

共同账户始终由稳定 collectiveId 控制；成员、选民或名称按有效章程改变时无须把钱过户给负责人。谁发起空账户不拥有单独提款权。共同资产不因为组名或头衔而归个人。

## 账户操作

- open：已激活集体的当前成员可登记空账户，余额严格为0；不会扣会费，不会制造组织之外的新义务。最多20个账户/集体，停用历史保留。
- contribute：本人选择对明确账户转账；真实扣本人余额。账户须open，收款版本精确匹配。贡献不自动产生份额、债权、投票权或未来退款权；想要这些关系需另立有效契约。
- transfer：只能消费集体已经通过的精确资源决定；绑定账户、收款对象、金额、原文说明和控制版本。决定不预锁钱，其他支出可能导致余额不足。普通余额增减不改控制版本，避免一次新捐款使整个已表决支出失效；状态/控制变更提升控制版本。
- begin-settlement：有效集体决定停止新收款和新义务；允许明确的清算支出，不能自动选择受款人。
- close：有效集体决定，余额必须为0且没有未释放预留/未完成义务。关闭不销毁钱，不删除历史，不自动关闭集体。

资金接收者支持真实居民、其他open共同账户、现有活动企业和国库。每账户入资最多10000笔，限额只限制新增入资，不能阻止已有资金支出/清算。每类结算调用所属领域端口：企业现金必须产生企业领域事件，国库使用既有明确集成语义，不能从钱包 reducer 偷改企业聚合。新增接收类型只有明确端口、守恒和测试后才开放。没有支持的资源操作明确拒绝。

资金精度沿用既有经济模型，所有金额/中间和/最终余额都必须finite且在版本化预算内；交易 entries 必须平衡。任何数值无法可靠表示的转移明确拒绝，不能让一方舍入出免费钱。

## 共同控制与原子执行

`collectives.propose` 的 resource action 在只读端口验证操作存在、参数闭合、账户确由该集体控制。执行时再次校验相同 action、当前章程权限版本、凭据状态和期限、账户控制版本/状态、余额与接收者。不能把一个低额决定改成高额支出，也不能把A集体的决定用到B账户。

执行预演生成：源账户领域事件、平衡交易、真实接收方领域效果、决定 consumed 事件。全部成功才提交一个journal记录；缺钱、权限变动、关闭、错版或接收方失败时所有领域保持不变，凭据保留。相同 requestId 重试返回原结果；不同 requestId 重放同一决定明确拒绝。

world端口只接受应用内部的精确授权校验端口，不向CLI开放自行填写的 authority=true 或 ownerId。domain不调用网络/文件/clock；事件包含最终余额与真实会计条目，reducer只复核和重建。

## 权限与个人经历

账户收款地址、标题、控制集体ID、收款状态和写入revision可按ID查询，便于自愿贡献；余额和完整交易仅当前控制集体成员可见。list不枚举不属于调用者的私密集体。外部出资者通过本人付款回执/经历知道自己的支出，不获得其他人的交易或集体章程。

查询返回每笔交易的真实出处：执行者、个人付款人或集体决定、双方会计账户、模拟时间、各账户实际revision与说明原文。账目按本账户revision排序，同一模拟时刻的交易也保持真实顺序。说明不成为客观履约结论。常态上下文只增加固定发现入口；详情和账目按当前权限分页，最多30项。出资/收款保存实际参与者经历，不捏造别人已读。

CLI方向：funds open/list/read/ledger/contribute；集体支出、清算、关闭通过明确resource action和collectives execute，不设置负责人快捷提款后门。Skill解释个人出资与集体授权、账户revision与controlVersion、失败不消费和真实会计部门。

## 资源连续性

M09继任来自既有章程程序；负责人离线不触发平台指定人选。退出或程序失去足够选民时资金仍存在且可对账，不能用平台暗中降低门槛解锁。原章程可预先选择较小签署集或安排继任修改；新加入者仍独立接受。

清算是有事实的过程：阻止新增义务、处理现有订单/托管/债务/预留、按有效决定分配余额、满足零余额/零义务后关闭。余额不为0时关闭拒绝；未接入的资产/义务不得在集体整体解散时忽略。后续W域接入会继续扩展资源盘点与清算端口，M09整体在这些路径通过后才能验收。
