# 有偿权利：接受、供给事实与价款结算

开发中，属于 W05 原定完整范围。依赖已经验证的定期许可和事实订单，不建立第二套产权或租约账本。

## 1. 付款不能代替权利，权利不能代替履约

居民选择使用范围、对象、价格、原始条款及合作主体。代码验证其当前权限和独立同意，原子提交“买方托管价款 + 指定许可被独立接受”。任何一步失败，两边都不提交；普通 `permits accept` 不能绕过已绑定订单先取得有偿权限。

该交易卖方是许可签发主体，买方是受让主体。供给是确定期限内合法、物理可用的使用权限，不是居民必须到场，也不是身体服务时长。shared 仍不保证设备闲置或排队优先。使用人仍自行决定何时使用，身体行动仍由本人开始。

有效许可、空间可用、实际参加、主观满意各有来源，不能互相冒充。代码不从合同原文推断房东信誉、房客满意或经营成功。

## 2. 所属领域和版本

premises 保存许可本身，以及仅对需要收费证据的许可启动的 `premises-provision-v1` 供给记录。每个许可最多一份记录，使用独立游标和修订，不把逐时段计量变成改写原始条款。记录保存已提供和不可用的毫秒数、已结算时间，以及所依据的真实建筑版本。没有记录的旧许可不补造过去的可用时间。

commerce 扩展为显式的 `resident-evidence-trade-v2`，增加定期许可这一封闭来源类型；既有 freight/service 订单保持原始结算解释。旧 v1 状态通过显式事件升级，旧历史回放不依赖当前默认值。新来源以许可原文版本和供给记录版本共同证明事实，CLI 仍只能传来源 ID/版本，不能上传“自己声称已经提供”的证据。

world 编排两聚合，独立比对原始资源事实，并将余额、共同账户、许可接受和供给起点放入同一原子事件。共同账户延续最大可能退款/收入空间及未清义务保护。新 policy 与 manifest、registry、命令目录、Skill 同步；禁止默默把 v1 订单的声明变成新事实。

## 3. 原子接受与绕过防护

卖方只能给尚未接受的许可报价，许可只绑定一个订单。价格基准包含原始 startAt/endAt、scope、使用人和模式；接受时复核建筑控制版本和冲突义务。买方的付款授权也必须覆盖这一份精确许可，集体执行绑定受让 controller 与决定凭据。

订单尚未付款时，直接领取关联许可被拒绝。买方接受订单时，代码从同一个提交前世界读取许可，验证付款账户和原始条款，执行许可接受并启动供给游标；付款不足、授权变更、排他冲突等情况均不部分成功。不能先写许可事件再以修改后的自身状态充当原订单的接受证据。

未接受报价可以按原规则撤回/到期。已接受许可不允许签发人单方撤销；受让人放弃未来使用前先结束真实工作，并结清到当前时刻的供给事实。放弃不会返还已经经过的有效供给时间，也不自动搬走人或物品。

## 4. 供给时间与物理边界

可计价窗口从实际接受与 startAt 的较晚者开始，到 endAt 或合法提前终止的较早者结束。每个时间片只结算一次。该时间片内许可仍有效、建筑 operational 且 condition 大于零，才记录可用供给；否则记录不可用期间。人数、实际劳动、付款和主观质量不从该计时中推导。

时间推进先结算过去区间，再提交该边界的老化、维修完成、终止等状态变化。房屋在边界损坏，不能据损坏后的状态抹掉之前已经提供的时间；维修完成也不能把之前不可用的时间补记成可用。关键变更须验证供给游标已到该边界，直接应用未结算的状态变化也不能旁路。

当许可结束且供给游标已覆盖终点，commerce 才能计算终态事实。可结算金额为总价乘以已提供时长除以原约定总时长，按货币微单位向下取整；迟接受、提前结束、物理不可用等未提供部分退款。自然期满不推定满意：已提供部分进入买方确认/双方争议和解，沿用既有托管程序。

期间计价的政策含义必须在 rules 和原始报价中可读。未来按次/固定交割等模式需要独立版本和明确接受，不能把自然语言中的价格措辞解释成任意扣款逻辑。

## 5. 权利与责任连续性

建筑控制交接保留许可和供给义务；其原交易当事方、收款账户不会仅因控制交接而被暗中改写。合同收益与责任转让需要各自有效授权。毁损、维修、占有、保管、欠付和公共救济仍由所属领域处理，不用冻结或删除订单代替。

有偿控制权交割是随后独立路径：精确绑定资源移交版本，资金释放与真正控制交接原子发生，保留资源已有义务。长期付款、续约、继任、清算、企业/家庭/公共采购和全运行模式仍在同一总目标内，本切片不删除它们。

## 6. 验收

至少覆盖个人和集体的原子接受；旧入口绕过；付款不足/授权失效/建筑版本或排他冲突时整笔不提交；过早/过晚接受；共享与排他；到期、主动放弃、部分不可用、损坏后维修；资金守恒、退款空间、微单位舍入；不同时间步长等价；重复命令和事件伪造；v1 历史、显式升级和 journal 恢复；真实 CLI/HTTP 与独立 Agent 路径。

供给计量仅为客观履约依据，工程脚本不证明社会自主采用；真实模型提示验收与无剧情自由运行继续分别记录。

## 7. 已接通的执行路径

`trades offer --source-kind permit` 绑定原始未接受许可；`trades accept` 在一个 `ResidentEvidenceTradeCommitted` 内提交资金、许可接受和供给启动。该封闭复合事件同时验证独立的提交前许可事实、逐人署名、集体决定和精确金额；删除或替换任一部分都会拒绝回放。原 `permits accept` 在报价未释放时拒绝旁路。

`ResidentPremisesProvisionCommitted` 只结算已有供给记录，不能自行启动收费。建筑变化前必须结清对应区间；老化/维修和许可结束先后顺序由 runtime 显式编排。逐时间片记录不会自动广播私人合同或生成每轮认知；实名使用人只收到权限接受通知，交易价格及账本仍须具有对应交易查询权。

新开放实验在相关能力齐备时记录 `resident-evidence-trade-v2` 和 `premises-provision-v1`；`paidPermits:false` 可保留 v1。旧 journal 只能由运行者 `enable-paid-permits` 显式升级，事件记录政策变化，旧免费许可、旧订单、资金和资产不变。共同账户的结算来源登记区分 `trade`/`trade-v2`，仍使用同一个实际托管账户，禁止未知来源或版本。

工程证据见 `SOCIETY_PAID_RIGHTS_VERIFICATION.md`。有偿控制权交割、长期义务、全运行模式和本批能力的独立 Agent 验收继续保留，不能由本节推断完成。
