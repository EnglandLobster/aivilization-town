# 条件、署名依据与有限制度执行（M07）

状态：契约完成，进入实现。依赖已验收的原文/共享记录/自定视图、精确委托、集体程序和真实共同账户。M08 的事件响应单独实施，不用本条件检查冒充事件调度。

## 边界

居民自己选择判断依据、条件和固定行动。平台验证来源、身份、当前可读性、比较运算、预算、授权与真实效果。文字“合格”不会变成客观质量；只能成为“指定居民在这个版本写下合格”的署名事实。通过集体表决、视图计算或签署说明都不会自生转账/身体/公权力。

协作域拥有封闭条件数据语言与版本、程序绑定和运行回执；information/world/collaboration 各自提供受权限控制的事实读端口。应用层在同一只读事务快照求值，再预演原有步骤，全部成功后提交。reducer只重放记录的结果，不重新读取现在的源数据。

## 数据语言与来源

program definition 保留既有 steps，可在显式启用的 resident-program-conditions-v1 中增加 conditions 数组（全部满足）。旧步骤定义与旧事件不变，没有条件时不添加新字段。

允许的来源：

- record：明确 register/key、字段、最新或精确revision、比较符与标量。结果是居民陈述上的判断。
- statement：record 的严格署名形式，另外指定 signerId；必须是该人实际编辑的版本，authorityId也必须是本人。被委托人代写不冒称本人亲自作判断；需要本人重新署名记录。
- view：明确view ID与精确定义版本，只比较定义中的聚合结果；保留view作者及源版本。居民计算仍是居民算法，不是平台信誉。
- clock：当前模拟时间这一公开世界事实。
- personal-fact：指定居民的余额、位置、可用时间或一项库存。沿用个人查询权限，程序的作者、所有可执行者、所有授权参与者都须有源读取权；现阶段只有本人能读其完整个人事实，因此跨身份程序不能用这种条件暗中窥探私人数据。可以自行明确发布共享原文，不能由系统自动代发。
- common-balance：明确共同账户及controlVersion，仅当前控制集体成员可读余额。
- decision：明确集体决定、章程授权版本与 passed/executed 状态；冻结决定与当前章程版本都须匹配，失效/过期依据不能继续当成有效程序条件。此条件只判断事实，不消费或授予该决定的资源执行权。

数值比较 eq/ne/lt/lte/gt/gte；字符串/boolean只eq/ne。不存在eval、宿主网络、文件系统、递归、自由函数名或LLM对原文的隐式裁判。unknown字段、非法数值、原型名称、错类型、缺失/撤下/无权源均拒绝。

## 权限与结果

每次运行先核对程序精确版本、执行者与全部个人委托；之后对程序作者、所有runners和所有principals检查全部条件源的当前权限。公开程序外观不能成为私有源读取代理。先完成全部读取权限检查，再暴露求值证据；权限不够时只有统一 source-unavailable，不透露值或局部求值结果。

运行证据逐条件记录：条件索引、来源类别、源ID和实际版本、匹配结果。没有复制原文或私人余额进所有人的经历。run查询本身仍只对既有参与者可见；每个人实际回执和查询受原预算控制。未满足条件保存失败原因与有权可见的来源证据，不执行步骤、不消耗付款/写入委托。原有定时任务遇失败停止；不会在后台无限重试。

精确record revision 与当前不符视为不可用，不能静默换成另一个版本；latest 每次重新读取并记录当次版本。view条件记录定义和原始输入版本。执行步骤可以在同一事务里写入条件源，但运行依据仍明确引用写入前版本，不混淆两个时间点。

## 预算与版本

最多8个条件，单条引用/比较结构有限；整个definition仍受既有12000字符预算，不能绕过步骤预算。每次条件总计算量最多100000，view的扫描/AST预算仍独立成立；超预算明确拒绝整次检查，不发布部分聚合。查询返回最多8条证据，无完整来源正文。

CoordinationState新增可选conditionsPolicy；显式ProgramConditionsEnabled事件幂等，不改变旧coordination policy的结算解释。新程序保存conditionPolicyVersion与不可变conditions。修订条件提升program revision，旧mandates失效，与改步骤相同。旧manifest默认不开启，operator enable-program-conditions仅追加事件。

新增 programs check --id --expected-revision 供被授权runner检查当前权限与条件，不执行步骤、不写run、不消费委托；实际run再次检查，check结果不是未来成功保证。默认上下文仅固定启用标记与Skill入口。programs read/history展开精确定义，runs展开受权证据；原始来源由其既有CLI读取。

## 当前操作范围

仍使用已有 payments.transfer、messages.send、records.put/append 四种可精确委托步骤；身体活动必须本人操作。集体共同支出沿用collectives.execute的实际决定，不因为条件通过而绕过或伪造这个权限。今后增加可委托操作必须同时明确真实执行者、principal和领域效果，不把改变白名单当作授权完成。

## 验证

覆盖：有权且满足时原子执行；false时无步骤/无授权消耗；签名/版本不匹配；原文和view计算不变成世界真相；权限撤回阻止计数/差异/失败原因泄密；他人个人事实不可作为读取代理；视图预算、除零和空聚合；修改条件废弃旧委托；多步骤失败整次回滚；check与run之间源变化重新验证；旧manifest/旧程序完全兼容；时间跨步、回放不再次求值；真实CLI两种不同用途和全仓回归。
