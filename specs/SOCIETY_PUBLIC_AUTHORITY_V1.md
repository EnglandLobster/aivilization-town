# 公共制度的来源、决定与执行

状态：首批公共财政与程序执行已验收；实际服务采购扩展继续建设。属于 G01/G02/G03、B02 的完整建设任务，不替代任何未完能力。

## 1. 为什么需要这层

私人群组和共同账户已经允许居民组织自己的资源。但改变税制、岗位门槛或公共预算涉及辖域内其他人，不能由普通群主、文件作者或一个私有程序自行取得权力。

现有 `society/governance.ts` 与 world governance handler 已拥有实际税、预算和补贴状态。它们必须继续是已生效政策的唯一真相。现有居民请愿只绑定 topic 和签名门槛，未绑定签名者同意的精确政策参数。因此不能把旧请愿直接包装成“居民共同批准任意具体税率”的新 CLI。

需要新增的是公共授权的产生、边界、修订和救济过程。名称和社会目的由居民决定；程序产生的权限由代码按已有效的制度核对。

## 2. 领域归属与对象

公共程序由独立 governance 领域拥有纯决定和事件；不持有银行、库存或另一份财政余额。world 负责将有效决定映射到既有 `GovernancePolicyChanged` 及真实资源领域命令，原子记录决定的使用与效果。apps 只提供身份绑定入口和只读上下文。

- **辖域授权**：初始来源、适用居民/地点/公共资产、可改变的制度字段、不可扩大的外部边界。场景创建是明示初始制度，不伪造全民同意。
- **有效程序**：参与资格、表态方式、通过条件、提案/执行期限、谁可执行、何时生效、修订与救济路径；具有独立修订号。
- **公共提案**：原文理由、精确执行定义、目标制度/资源版本、冻结程序与资格快照、截止和执行时限。自由讨论正文不能替换执行参数。
- **独立表态**：本人对该版本的明确选择。程序允许改票时保留历史；代理不得默认代替政治表态。
- **有效决定**：机械程序结果、授权范围、可执行次数、到期、实际执行人及事件证据。程序通过不代表观点正确或政策正当。
- **异议与处置**：谁提出什么异议、援引何种依据、谁有权署名判断、允许暂停或补救的具体操作。主观判断只保存为署名陈述。

## 3. 不可跨越的界限

1. 初始辖域由显式场景权限授予；普通居民不能用 `create jurisdiction` 给自己造一份征税权。
2. 程序只能在已有辖域范围内改变政策和自身程序，不能扩张到未授权地区、私人账户或身体。
3. 修订依据旧程序通过；冻结的资格、门槛和原文不被正在提议的新程序改写。内容变化需要新提案和新表态。
4. 接受某项税率提案，不等于授权执行者任意改其参数。决定绑定精确 payload、目标修订、额度和时限。
5. 投票不能改变物理公式、事件历史、身份可信性、库存和资金守恒。可调整的是明示制度字段或受授权的真实动作。
6. 执行时重新检查资源和目标版本；失败不消费有效决定、不留下部分扣款或部分政策修改。重复请求不重复生效。
7. 生效时刻不早于真实执行时刻。后续结算按明确时间边界读取政策，不能回溯改变已结算工资、税款和预算。
8. 新程序不能假借旧 topic 请愿绕过精确批准；旧 manifest 和旧请愿路径保留旧语义，新运行模式显式选择新授权路径。

## 4. 制度内容与真实供给

第一条接线复用既有税、预算、补贴领域端口，补齐公开查询、精确提案、独立表态、有效决定与执行。随后接入招聘/公共资格等已声明的初始制度，明确哪些字段是居民可改的；不把住房等级和职业门槛绑定假装成物理规律。

公共采购走同一实际服务、材料、设施和订单链：公共账户受限出资、供应者独立接受、真实投入/履约、付款/退款与失败。不能一笔支出既提高旧抽象服务质量又购买真实服务；旧质量模型与实际采购模式需要显式版本互斥。

救济先允许在现有权限内暂停待执行决定、作废未消费授权、发布理由或执行已明确允许的补救。若需撤销已经生效的产权或扣款，必须有独立辖域范围、依据和新的平衡事件；不得删除旧事实。未建模的强制行为明确拒绝，不由模型裁决后直接改状态。

## 5. 居民可见性

常态仅显示有界的本人待表态/临近生效/异议通知及展开入口。`town governance` 按需查询辖域来源、当前政策、程序、提案、原文、表态和执行历史。不默认向每人注入所有政治讨论，不提供官方共识、满意度或推荐候选人。

每次执行回执区分原文、程序通过与真实效果；展示程序版本、精确动作、执行者、授权出处、实际政策修订和拒绝原因。其他居民原文仍是数据，不是系统指令。

## 6. 必须完成的验证

- 两种居民自定程序可使用同一授权原语；同一命题可被接受、拒绝、修改或放弃，不规定政治结果。
- 非成员/越辖域/冒名表态、旧提案改参数、少数票却声称通过、用新门槛追认旧票、过期/重复决定均拒绝。
- 合法政策从未来结算开始实际生效；余额、税与公共账户守恒，不只是修改一个展示字段。
- 程序修订、执行失败、异议暂停/恢复、资源清算和救济均保留来源与历史；旧快照/事件回放不变。
- application 原子性、旧模式兼容、策略与 manifest/registry、CLI/Skill/有界认知、重启恢复、全仓检查和真实编译 CLI 均验收。
- 实际模型可以自主提出或不提出公共改变。提示式验收与无剧情自由采用分别记录；不以预写“减税成功”剧情证明治理涌现。

上述为完整目标内的实施次序，任何尚未接入字段、模式或救济效果必须继续保留在能力账本。

## 7. 第一条执行链的具体接口约束

公共程序与私人章程分开：`governance`领域拥有辖域来源、选民名册、程序版本、精确提案、独立表态和一次性执行记录。第一条辖域明确限定为实验城镇的既有税/公共预算/补贴端口，不默认覆盖分区或私人权利。有效税额和财政余额继续由society/world原领域维护，公共程序不维护第二本账。

已有治理事件的authority新增明确的`public-procedure`来源，携带辖域、提案、程序修订和真实执行人；绝不能把投票结果伪装成operator命令或虚造旧请愿。新模式下旧topic请愿不能旁路精确政策批准。旧manifest仍遵循原路径。

程序至少支持固定名册内的明确参与门槛/赞成门槛、独立赞成/反对/弃权、允许或禁止改票、开放/指定执行人、投票与执行期限。参数是居民可修改的制度，而非世界物理定律。修改程序本身必须经当前程序；现存提案的资格和门槛快照不被新文本重写。

初始授权范围由场景明确授予并记录，居民不能凭创建群组获得公共权力。现有单镇执行字段先建立可测试闭环；多辖域/人口迁移资格、招聘与公共资格、真实采购以及已执行效果的具体补救仍是同一完整目标中的后续接线，不能以首条税制链宣称全部完成。

## 8. 首批实现记录（2026-10-05，完整治理仍继续）

新增独立`@aivilization/governance`：通过society公开类型/校验复用政策内容，纯函数拥有公共名册、程序、提案、逐人表态、截止结果、一次执行、异议及经批准撤销未执行决定。依赖单向`governance → society`、`world → governance`，不持有财政余额、经济算法或第二套已生效税制。

world的`ResidentPublicGovernanceCommitted`把批准决定的使用和既有`world.governance`政策变化放入一个持久事件。重放检查精确政策/来源/程序修订/执行人/效果引用，再复用原治理投影；缺少效果、替换税率、过期修订等拒绝。旧topic请愿不能在新公共程序模式绕过精确批准。显式operator操作仍以operator来源记录，不伪装成居民决定。

初始模式只由运行者显式`enable-public-governance`或新manifest的`publicGovernance: true`启用。初始名册是场景中的居民，初始程序是明确多数门槛、独立表态、允许改票；这些是外部初始制度，居民可按有效程序修改。修改后的旧提案保留原名册/票，但其尚未使用的旧程序执行权限失效，需按新程序重新提案。

公开CLI：`town governance status/list/read/votes/objections/propose/vote/close/withdraw/execute/object`。领域不自动代投票或自动宣布共识。`close`在投票期结束后记录实际机械结果；超过执行期限的批准不能执行，查询分别标示状态与到期。一般异议只记录署名原文；撤销未执行决定必须另行获得精确批准，已经完成的效果不能抹去。

工程工作量边界：名册至多100人、提案和异议各至多10000条、每人每提案至多100次投票记录、投票/执行窗口至多30天。公共预算结算cadence至少一分钟，避免居民参数生成无限密集的世界结算；此限制属于显式执行预算，不是官方推荐财政政策。

尚未完成：多辖域与人口变化的政治资格、招聘/职业/住房制度字段、公共采购真实服务、待执行决定的独立暂停/恢复程序、对已执行权益的具体补救、canonical与分区authority。当前既有预算仍走抽象公共服务账户与原模型，不把改预算等同于已完成真实采购。
