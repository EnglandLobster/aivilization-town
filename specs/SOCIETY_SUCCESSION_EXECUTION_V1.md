# 有限继任执行与实际资源效果

状态：开发中。此Spec推进原M09/W06/W08，继任安排/现金/身体与银行是前置能力，不改变原25项完整交付范围。

## 边界

居民本人预先选职责、资源与人选；执行人与受益人独立接受精确条款。正文、家族身份、管理头衔不产生权力。真实永久人口事件触发已经准备好的安排，不用供应商失败/离线推定死亡，不选默认继承人。

执行人是独立真实actor，不伪造死者本人命令。其受托权限仅是原条款中的资源与操作；资源控制、现金、产权、库存和原作者仍归各自领域。身体不存在不等于原金融主体或原资源义务消失。

## 完整执行范围

1. 控制交接：现有stock/vehicle/premises/space/register/view/group/service逐资源精确版本的提议，受益人再独立接收当前实际交接。不自动入群、解密、搬动物品、驾驶、入住或获取职业资格。
2. 原现金责任：实际既有支付、退款、债权与费用按原约定继续；执行人只能用明确金额上限和真实支出用途，不将余额当其私产。受益分配必须在完整责任/争议/保留资金证明下执行，不能先分资产再逃债。
3. 原背包及实物：保留地点、来源、数量、受托标识、运输与返还空间；领取需要实际本人到场、可用时间和载荷，不瞬移，不夺取受托货物。
4. 原资本权益：产权份额、管理角色、利润与未清债务分开，受益人接收原权益不自动成为经理/员工。原企业独立资产不得因自然人死亡烧掉或变成个人遗产。
5. 原存款本金和未偿贷款：固定银行主体、原仓位和授权范围；不为新借款、无限提现、默认免债打开后门。原银行不足与困境责任单独保留。
6. 退出与收口：全部11责任域按自己的真实事实查询，缺失保留UNKNOWN与原因。只有资产/义务/争议和实际效果结清才关闭；容量和历史归档在入镇/建约前预留，不能因配额阻挡真实死亡。

以上均属于目标，控制提议切片不能取代剩余范围。

## 首条控制提议执行机制

society拥有独立SuccessionControlExecution记录：精确安排/条款版本、实际人口事实、原资源种类/ID/控制版本、实际executor/beneficiary、当前拥有领域sourceRevision、发生时刻与有限截止。只记一次确实提交的提议，不建立第二份资源所有权表。

每个原绑定至多一次提议机会；不能重用陈旧凭据、替换受益人、扩展资源或在过期后续权。修改条款不继承旧同意。准备只产生待原子提交的领域事件；所属资源实际offer和该记录在同一journal提交。拒绝不消耗执行机会，不留半个控制提议。

authority仅验证版本化的有限委托来源与整个offer请求，不能访问society/world。真实安排/人口/当前权限由world或开放journal拥有者独立核验。其source是succession，实际actor仍是执行人，不能伪装personal。源只能发给指定居民beneficiary的offer，不能授权生产、通信、编辑、转账或accept。受益人的accept仍走本人当前认证；已有资产用途、材料/服务/租约/物流义务与作者不因控制变更丢失。

原v2个人/公共/企业/集体凭据保持原语义；新增来源有自己的明确版本，新可选执行策略须显式启用，不能因读取旧快照出现。现有世界普通操作入口不能接受只有结构正确而无实际来源的委托。

## 协调与可感知性

world拥有的资源通过其公开拥有领域端口协调；information/services等开放journal资源由worker提供当前授权只读端口，仍用一个单写入journal原子提交。domain不依赖apps/world，reducer只重放事实与独立核验来源，不重跑继任决策。

常态预览只有当事人的状态与主动查询指针；原条款、当前绑定、拒绝原因和执行记录按认证分页读取。旧消息、文件、密文和财务不因“受益人”公开。真实执行回执与模型会话历史分开，限额/排序/阶段可见性按RESIDENT_CONTEXT_DELIVERY执行。
