# 事实订单基础验收（W05，2026-10-05）

本切片完成商品/服务订单与真实货运、本人参与、共同账户和集体决定之间的连接。居民制定价格、对象和原文条款；代码保证同意、原始事实、账目与结算。W05 的产权/使用许可和长期义务仍继续开发，不能据此将完整 W05 标为完成。

## 已验证的边界

- `commerce` 的独立版本订单引用一个尚未开始的货运或实际服务过程，原来源只绑定一次。卖方提出，买方按精确版本独立接受并托管。未经付款，实际装载或开始服务会被应用入口与事件回放共同拒绝。
- world 从物流/服务权威状态取得证据；即使伪造的订单事件与其自带证明完全自洽，所属领域没有发生相应事实仍拒绝。订单不会复制物品，也不从文字制造到货、劳动或身体效果。
- 商品实际送达后等待买方确认；取消在途货物保留货物与托管，实际退回后商品款退款。承运费用单独按原货运合同结算，不与商品价款混合。
- 服务源采用零时薪，由订单单独计价。按已记录的本人实际重叠时长计算可结算部分；未履行价款退回。赞助付款方与身体参与者可以不同，付款不授予他人身体控制权，订单收入也不自动成为工资。
- 争议是署名原文；实际履约不自动判定满意。和解绑定当前版本，由对方独立同意。普通争议达到陈述配额后，已有款项仍可协商结清，不因文本配额被永久锁住。
- 个人与集体身份分开：同一个人可以执行获正式表决授权的集体动作，回执保留本次代表的一方和决定凭据，不误用其个人身份。集体资源名支持真实 CLI 连字符路由，封闭操作授权仍保留。
- 托管属于 `public-service:resident-evidence-trade` 流通账户。实际收付与共同账户为平衡转账；共同账户预留退款及收入空间，不能用新出资挤占已承诺的退款容量。
- 列表按 ID 排序，原始账目按实际订单 revision 数值排序。同一模拟时刻超过十条回执、journal 键顺序规范化和重启不会改变分页顺序。承运人和服务受益人不因身体参与自动获得价款当事方权限。
- 旧 manifest 和旧订单保留语义；显式 `enable-evidence-trade` 只开启空聚合，不改变资产、身体或旧记录。新 manifest 记录策略来源。
