# 交易、权利与长期义务的边界

本文件落实总 Spec 的 W05，并连接 W04、W06、M09、G03。整个范围包括实物、服务、产权/使用许可和长期义务；下面的实施顺序不删除任何一类。当前处于开发中，不能据此声称已经具备全部功能。

## 1. 谁决定什么

居民决定交易对象、价格、用途、合作关系、质量标准与争议主张。代码验证当事人同意、实际控制权、资金来源及交付事实；不从评价文字推导质量、药效、产权或劳动。CLI 提交意图和精确版本，不能提交一个自称真实的“交付证明”。

交易是 commerce 的聚合。实物保管属于 materials/logistics；实际服务属于 services/society；建筑、设备及其许可属于各自资源聚合。world 从这些权威状态取得事实，在一个命令中协调交易和账目。commerce 不导入 world，也不复制运输、医疗或建筑规则。

旧 resident-commerce-v1 的报价、订单、付款、押金和历史事件保留原语义。其报价入口已经拒绝远程商品；服务交付仍是当事人声明。新交易使用 commerce 包内独立版本的订单聚合，明确引用实际履约来源，不为旧订单补造事实，也不把同一订单复制到两个账本。新自主模式最终须关闭旧声明式订单的新建入口，已有订单仍能查询、结清。

## 2. 以事实为依据的订单

第一条实现路径采用 `resident-evidence-trade-v1`：卖方提出精确条款，买方独立接受并托管款项，履约来源只绑定一次。个人或集体都可成为当事方；集体操作必须使用绑定精确操作的有效决定，头衔、创建者和普通成员身份不构成权限。付款和收入账户分别由对应当事方控制。

订单保存原始条款、认证执行者、来源版本、各次事实回执及财务结果。新的货运/服务过程在报价前必须尚未开始；报价有效但尚未付款时，关联过程不能开始消耗或装载。卖方可撤销未付款报价，届时解除开始限制。已经付款时不能仅取消订单就退钱并抹掉在途货物。

实物订单引用一个真实货运过程：来源控制者是卖方，目的库存控制者是买方，原始物品与两端地点固定。承运费用仍属于货运合同，商品价款属于订单，两者分别展示。货物实际交付后才进入买方确认；取消/退回必须等货运领域出现对应终态才退款。搬运、交付不会在订单里再复制一份库存。

服务订单引用一个真实服务过程：卖方控制供给，指定受益人必须亲自接受/参与。买方可以与受益人不同，例如共同账户购买成员照护。为避免同一服务隐式重复计费，该路径只接入自身时薪为零、由订单单独计价的服务。订单明确最大时长与总价；提前结束按实际重叠时长比例计算可结算金额，微单位向下取整，未履行部分退回。订单价款不自动成为提供者工资；分配需要另行授权的真实付款，W06 继续接入劳动报酬。

履约事实和满意程度分开：客观交付后买方确认释放款项；争议保存各方原文，托管保持不动。和解明确退款额，绑定当前订单版本，由对方独立同意后执行。平台不自动认定质量，不因超时推定满意。卖方可放弃待收款；退款不自动把已交付物品从买方处拿走，也不逆转已发生的身体或学习效果。

期限只改变明确的程序状态：未接受报价到期可关闭；已付款但来源未终结则保持待履行/待返回，不凭空退回物品或清空托管。自动推进必须逐项读取真实终态，不能悄悄替居民确认质量。当前授权失效时保留待处理义务，交给有效继任或公共救济，不能指定默认继任者。

## 3. 权利移交与使用许可（完整范围，继续实现）

买卖控制权与购买使用权是不同契约。资源控制移交必须锁定具体对象、原控制版本和买方，按该资源自己的移交决定完成；付款与控制权变更同一原子提交。普通资源移交入口不能绕过已绑定的有偿交割。资源上的既有租约、保管、劳动与债务不会随改名或卖出消失。

空间/设施使用许可至少记录授予主体、对象、用途范围、使用人、时段、容量、撤回/终止条件和有效程序。许可不会成为所有权，也不能超出授予者本身的权限。相互冲突的排他使用时段不能双重出售；非排他访问许可仍受真实容量和本人到场约束。租金/使用费按明确的实际有效期间结算，不由文件标题产生权利。旧公共住房不通过迁移赠予个人。

该部分的领域顺序是：premises 的真实使用许可与义务索引；society 既有租约对接；各资源的有偿控制交割；最后连接订单的权利交付证据。不得先做一个能改任何资源的通用 ownership 字段。

## 4. 长期义务与终止（完整范围，继续实现）

长期约定必须拆成精确的未来可执行义务：付款方、收款方、周期/到期、上限、终止与争议程序、来源授权及当前未清余额。自然语言约定可以保存，但不能直接授权无限扣款。双方独立接受后，代码才可按明确规则尝试已授权付款；余额不足记录欠付，不暗中铸币、强制劳动或建立未经接受的借款。

本金、利息和信用违约仍归 credit；租住占有与租金归 society；已履行服务/货物的价款归 commerce。不能新增第二套贷款/租约真相。周期命令通过相同聚合执行，保存到期游标和幂等标识；多周期推进与逐期推进等价。

撤销代理不抹除既有债务。解散、死亡、失能和控制权交接先阻止新义务，再按有效程序处置原义务；无继任依据时保留冻结、可查询且可救济的状态。清算资金必须能追到付款/退款双方，余额与未付债务分别展示。

## 5. 数据与执行契约

事实端口只返回封闭的货运/服务/权利事实类型，由 world 填充；CLI 仅传来源 ID 和期望版本。持久事件记录当时采用的最终事实，reducer 机械验证账目与事实对应关系，不重跑当前政策。独立比对来源事实，禁止从待写事件自身取“证明”。同一来源不得被多个订单重复占用或重复结算。

托管使用明确的流通账户，并纳入 moneySupply、公共服务账户构成与恢复对账。所有交易都有平衡 entries。共同账户同时预留最大可能退款/收入的余额空间，不能等实际退款时才发现已被关闭或塞满。

查询按当前双方控制权授权，历史作者不保留私密账单访问权。列表/回执分页，常态上下文只提供有限入口与本人经历；不注入全城订单，不为买方自动写满意评价。CLI、规则目录、Skill、能力契约、manifest 与 provenance 同步。

## 6. 实施和验收账本

1. 证据订单领域：独立同意、一次来源绑定、托管、真实履约、争议/和解、原始账目和旧状态兼容。
2. world/居民入口：货运及服务只读证据端口、开始限制、共同账户、原子事件、回放、实际 CLI 和集体决定。
3. 权利：空间/设施使用许可、有偿控制交割、已有租约/责任连续性。
4. 长期义务：有效授权、周期执行、欠付与终止，连接 credit/租约/企业工资；不复制领域真相。
5. 整体验收：商品异地交付、共同购买实际服务、空间使用交易、控制权交割、跨周期欠付/退出/清算，以及不同治理方式下的独立 Agent 组合。

每步覆盖成功、拒绝、非法数值、版本冲突、重复提交、权限失效、旧快照、来源伪造、跨聚合失败和全账户守恒。完整 W05 只有上述五步全部有对应证据才能标为完成。真实模型被提示使用、自由运行自发采用和确定性工程测试分别记录。

第一、二步的领域与居民路径已经接通：`packages/commerce/src/trade*`、`packages/world/src/residentEvidenceTrade.ts` 与 `apps/worker/src/openSociety/evidenceTrade*`。入口为 `trades`，版本为 `resident-evidence-trade-v1`，托管账户 `public-service:resident-evidence-trade`。新 manifest 显式记录来源；旧 journal 通过 `enable-evidence-trade` 启用空聚合，不回填旧订单。

集体执行端口限定本次代表的 controller；同一个自然人既是个人卖方、又是买方集体获授权执行者时，独立表决凭据和本次代表身份分别记录，不能误用其个人身份替代集体同意。旧 collective 资源名校验补齐实际 CLI 中已有的连字符语法，执行权限仍由封闭 adapter 验证。

普通争议陈述有数量上限；达到上限不阻断已有托管的双方和解或卖方放弃收款。和解原文在不可变回执保留，当前提案按精确版本响应。资金去向始终可对账，不能借文本配额强迫一方接受退款或支付。

此记录不把后续第三、四、五步标为完成；验收门禁与原始证据见单独的验证报告。
